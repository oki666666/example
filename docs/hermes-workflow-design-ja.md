# Hermes Agent ワークフロー設計（タスク管理・MTG・振り返り）

このドキュメントは、Hermes Agent を日常業務に組み込むときの設計例です。

---

## 1. 設計の全体像

以下の 3 レイヤーで考えると運用しやすくなります。

1. **入力レイヤー**
   - MTGメモ
   - タスク一覧
   - カレンダー情報
   - Slackでの追加指示
2. **処理レイヤー（Hermes）**
   - 要約・分類
   - アクション抽出
   - 優先順位付け
   - 定期ジョブ実行（cron）
3. **出力レイヤー**
   - Slack通知
   - 日次/週次レポート
   - 次の行動提案

---

## 2. 推奨ワークフロー

### A. MTG前フロー（開始30分前）

1. 定期ジョブが起動
2. 直近の議事録と未完了アクションを取得
3. 「今日決めるべき論点」を 3 つに圧縮
4. Slackに事前ブリーフを送信

**出力テンプレート**
- 会議目的
- 前回の決定事項
- 未完了アクション（担当/期限）
- 今日決める論点 3 つ

---

### B. MTG後フロー（終了直後）

1. 会議メモを Hermes に渡す
2. 決定事項 / 保留事項 / アクションを分類
3. アクションに担当者と期限を補完
4. Slackに共有し、翌日のリマインド対象へ登録

**運用ポイント**
- メモは完全でなくてよい（箇条書きで十分）
- 期限が無いアクションは必ず仮期限を付与して未設定を防ぐ

---

### C. 日次振り返りフロー（終業前）

1. 当日の完了タスク・予定外対応を収集
2. 計画との差分を抽出
3. 明日への改善アクションを 1 つ選定
4. 振り返りログを保存し、週次レビューに引き継ぐ

**出力テンプレート**
- 今日の成果 3 点
- 詰まりポイント 2 点
- 明日改善する 1 アクション

---

### D. 週次レビュー（週末または週初）

1. 日次ログをまとめて圧縮
2. 未完了の根本要因を分類
3. 来週の重点テーマを 3 つ定義
4. 不要タスクの削除または委譲候補を提示

---

## 3. データ設計（最小構成）

Hermes 側のメモリやスキルを活かすため、入力を最低限の構造で統一します。

### 3-1. タスク項目（推奨）

- `title`: タスク名
- `owner`: 担当
- `due_date`: 期限
- `priority`: high / mid / low
- `status`: todo / doing / done / blocked
- `source`: mtg / backlog / adhoc

### 3-2. MTGメモ項目（推奨）

- `meeting_name`
- `date_time`
- `participants`
- `decisions[]`
- `open_questions[]`
- `actions[]`（owner, due_date を含む）

### 3-3. 日次ログ項目（推奨）

- `date`
- `planned_tasks[]`
- `completed_tasks[]`
- `interruptions[]`
- `learnings[]`
- `next_action`

---

## 4. 通知設計（やりすぎないコツ）

通知が多すぎると定着しないため、最初は次の 3 種だけに絞るのが安全です。

1. **会議前ブリーフ（30分前）**
2. **会議後フォロー（終了後）**
3. **終業前の振り返りリマインド**

慣れてきたら以下を追加します。
- 期限前日リマインド
- 週次レビュー配信

---

## 5. 権限と安全設計

Hermes は実行系ツールまで触れる構成にできるため、初期は安全側で設計します。

- 書き込み系操作は明示許可制
- 外部送信先は業務チャネルに限定
- 個人情報を含むログは要約して保存
- 「自動実行」と「要確認実行」を分離

---

## 6. 導入ステップ（段階的）

1. **Phase 1: 読み取り中心**
   - MTG前ブリーフと日次振り返りだけ運用
2. **Phase 2: 半自動化**
   - 会議後のアクション抽出と期限リマインドを追加
3. **Phase 3: 自動化拡張**
   - 週次レビュー、タスク棚卸し、習慣化ダッシュボード化

---

## 7. すぐ実行できる運用例（1日の流れ）

- 09:00: 今日の優先タスク提案を受信
- 10:30: 11:00 会議の事前ブリーフを受信
- 12:05: 会議後サマリーと宿題一覧を受信
- 18:00: 日次振り返りの質問を受信
- 金曜 17:30: 週次レビューを受信

この形にすると、タスク管理・MTG・振り返りが 1 本の運用ループとしてつながります。
