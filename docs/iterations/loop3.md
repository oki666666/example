# Loop 3: 信頼性・UX改善（エラー回復/A11y/Undo/エクスポート）

## 前ループからの課題（改善前）
- 失敗時のリカバリー導線が弱い
- 削除ミス時に復元しづらい
- キーボード操作や通知UIが不足
- データ持ち運び手段がない

## STEP5 改善案（実行内容）

### 何を削るか
- 物理削除をやめ、削除操作をアーカイブ化（可逆性重視）

### 何を足すか
- APIエラー分類（code付き）を前提にしたユーザー向けメッセージ
- 削除後Undo（8秒）
- 楽観更新のロールバック（ステータス更新・削除）
- キーボードショートカット
  - `/` で検索へフォーカス
  - `Alt + N` で新規タスクタイトルへフォーカス
- JSONエクスポート

### 設計変更
- `DELETE /tasks/:id` をソフト削除化（`archivedAt`更新）
- `POST /tasks/:id/restore` 追加
- `GET /tasks/export` 追加

### 技術変更の是非
- スタック変更は不要
- 既存APIを拡張する形で実装可能と判断

## STEP6 再設計＆再実装（結果）

## バックエンド変更
- `DELETE /tasks/:id` はアーカイブ化して削除扱いを返却
- `POST /tasks/:id/restore` で復元可能
- `GET /tasks/export` でJSONスナップショットを返却
- APIテストを拡張（復元/エクスポート）

## フロントエンド変更
- `ApiClientError` を導入してエラー種別を保持
- エラー時に再試行ボタンを表示
- 成功通知・Undo通知をバナーで表示
- 削除・状態更新は楽観更新し、失敗時にロールバック
- A11y改善（aria-label、alert/status領域）
- JSONエクスポートボタンを追加

## テスト結果（Loop3）
- サーバーテスト: 8件成功
  - Loop2までの6件
  - 削除アーカイブ&復元
  - JSONエクスポート
- Webテスト: 1件成功
  - フィルタ操作時のイベント通知
- ワークスペース全体テスト成功（`npm test`）
- Webビルド成功（`npm run build --workspace web`）

## 自己評価（自己批判）

## ユーザー視点での問題点
- Undo対象は直近1件のみで、複数連続削除に弱い
- 通知の自動クローズ制御が未整備

## 技術的負債
- Appコンポーネントに責務が集中し始めている
- APIクライアントのエラー型は拡張余地がある（詳細code辞書化）

## スケーラビリティ課題
- ページング未実装のため、大規模件数では転送量が増える
- エクスポートは全件一括で、将来ストリーム化が必要

## UXの弱さ
- モバイルでの一括操作導線がまだ窮屈
- アーカイブ管理専用画面は未実装

## 改善前後の違い・判断理由・トレードオフ
- 改善前:
  - 失敗時に不安、誤削除の心理的コストが高い
- 改善後:
  - 失敗時の再試行・Undoで回復しやすくなった
  - 操作ショートカットと通知で日次操作が軽快化
- 判断理由:
  - 継続利用を決めるのは「機能数」より「壊れにくさ」と「回復しやすさ」
- トレードオフ:
  - UI状態管理（通知・Undo・ロールバック）が複雑化
  - テストすべき分岐が増加
